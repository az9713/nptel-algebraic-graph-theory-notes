# Lecture-note production workflow

This independent study edition follows the root-level HTML chapters, provenance sidecars, bundled offline reader, source map, executable laboratory and separate evidence records of the earlier NPTEL and Stanford lecture-note projects. Production uses the transcript-grounded-textbook, rigorous-explainer and science-editor skills. Source acquisition and chapter review remain in progress until the completion record says otherwise.

1. Enumerate the supplied playlist exactly, retain every source identity and verify course attribution with NPTEL. This playlist contains 45 entries for 44 numbered lessons; the repeated balanced-signed-graphs title is investigated rather than silently discarded. Official live sessions outside the supplied playlist are excluded.
2. Prefer complete published captions. Record unsuccessful endpoints. When captions are unavailable, acquire permitted audio locally and transcribe with faster-whisper small.en. Compare decoded waveform duration with recording duration and retain media hashes; container bitrate estimates are not duration evidence.
3. Read each assigned transcript sequentially and map topics, examples, distinctions and uncertainties to the chapter outline. Titles and course concepts do not establish transcript reading. Machine recognition cannot guarantee board-equation accuracy.
4. Calibrate one complete pilot against representative earlier chapters. Develop original exposition with explicit definitions and assumptions, sustained proofs, recurring cases, computed checks, useful figures and fully worked exercises. Keep original teaching constructions distinct from lecture statements.
5. Inspect primary authored mathematical references for the exact claims cited. Record the edition and locator. Distinguish a proved mathematical result, a finite software check and a reported research result.
6. Obtain independent scientific reviews, repair findings and obtain a second review. A substantive rewriter becomes an author of that text. Bind final zero-blocking verdicts to the exact authored-body digest, retaining an honest description of review scope.
7. Wrap chapter bodies in the shared dark reader without altering their content. Bundle CSS, JavaScript and MathJax for offline reading, search, navigation, theme/text controls, solutions, printing and code copying.
8. Execute every authored program and compare actual outputs. Check timestamps, identity coverage, source boundaries, body hashes, local links, mathematical rendering and desktop/mobile browser behavior. These checks do not substitute for scientific review.
9. Audit the public inventory, rebuild a source-free export and publish only reviewed deliverables. Commit and push to a separate course repository; verify served bytes, representative reader controls and the README preview. Raw audio, transcripts, downloaded references, internal reviews, caches and logs remain in ignored work/.

No full audiovisual review, formal proof verification or guarantee about scientific correctness is implied by automated validation. The manifest, sidecars, editorial records and completion record describe what was actually checked.

Accepted chapter digests are computed over the exact UTF-8 bytes between the BOOK-CONTENT markers. The shared reader decodes read_bytes() without newline translation. Git attributes disable line-ending conversion for all package files so Git archives and served-file hashes preserve the reviewed bytes; do not silently normalize an accepted body. Scientific re-review is required if those bytes change.

Final release inventory is explicit and mandatory with tools/audit_public.py --release. Exact chapter HTML and metadata filenames must match source-manifest.json; source-free Git exports and live probes always use that strict inventory. Whole-book browser validation awaits asynchronous code-copy completion before evaluating its visible result, including the selected-text fallback.

Both independent rounds1/2 must accept each exact current body, have distinct named reviewers and no unresolved findings. Formatting-only amendments preserve and validate the prior full-science chain. Strict release gates also enforce full source reading, current chapter hashes, every numerical listing and all40 reader page/viewport checks. The first live probe explicitly uses --bootstrap while the served report is pending; final probes require served_report_passed=true. tools/audit_public.py --complete additionally requires completed source-free/live evidence and final completion state.
